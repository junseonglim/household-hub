# 모듈: 요리

> 상태: v0.2 (M3 구현 반영) · 2026-10-12 · 사용 테이블: recipe, recipe_ingredient, meal_plan_entry, shopping_item

## 1. 목표

"오늘 뭐 먹지?"를 매일 고민하지 않도록 한 주의 식단을 미리 함께 짜고, 식단에서 바로 장보기 목록을 만들어 장 보면서 함께 체크한다. 우리 집 레시피를 한곳에 모은다.

흐름: **레시피 → 주간 식단 → 장보기 목록**

## 2. 사용자 스토리

- 가족으로서, 우리 집에서 자주 하는 요리의 재료와 순서를 한곳에 모아 두고 싶다.
- 관리자로서, 주말에 다음 주 식단을 짜고 누가 요리할지 정하고 싶다.
- 구성원으로서, 오늘 저녁 메뉴와 내가 요리 담당인지 바로 알고 싶다.
- 구성원으로서, 이번 주 식단에 필요한 재료를 장보기 목록으로 한 번에 옮기고 싶다 (집에 있는 건 빼고).
- 장 보는 사람으로서, 마트에서 한 손으로 항목을 체크하고 싶다.
- 가족으로서, 누가 무엇을 샀는지 알고 싶다 (중복 구매 방지).

## 3. 기능

### MVP

| 기능 | 내용 |
|---|---|
| 레시피 | 제목, 기준 인분, 조리 시간, 재료(이름 · 양 · 단위 · 메모), 조리 순서, 출처 URL, 태그 |
| 레시피 목록 | 검색, 태그 필터, 레시피에서 바로 '식단에 추가' |
| 주간 식단표 | 날짜 × 끼니(아침 · 점심 · 저녁 · 간식), 한 끼에 여러 메뉴, 레시피 선택 또는 직접 입력, 외식 · 배달 표시, 요리 담당자 |
| 식단 복사 | 지난주 식단을 이번 주로 복사 |
| 장보기 목록 | 빠른 추가, 카테고리별 묶음, 체크(누가 · 언제), 체크한 항목 정리 |
| 식단 → 장보기 | 기간을 고르면 필요한 재료를 모아 미리보기 → 고른 것만 추가 |

### 이후

- 실시간 동기화 (장 보는 중 다른 사람의 체크가 바로 보이기)
- 레시피 사진, 레시피 URL에서 자동 가져오기
- 인분 조절 (재료 양 자동 계산)
- 냉장고 재고 · 유통기한
- 자주 사는 품목 · 자주 먹는 메뉴 추천
- 아이 알레르기 재료 경고 (육아 모듈 연계, 화면 계층에서 조합)

## 4. 화면

### 4.1 이번 주 식단 — `/cooking` (기본 탭)

- 주 이동 `◀ 10/5 ~ 10/11 ▶` (`/cooking?week=2026-10-05`, 한 주 = 월~일), [지난주 복사].
- 날짜별 카드 목록 (휴대폰 · PC 같음). 이번 주는 **오늘부터 위에** 보여 주고, 지난 날은 아래에 접어 둔다.
  - PC용 7열 × 끼니 그리드는 이후 (앱 본문 폭이 좁아 카드 목록으로 시작).
- 메뉴 이름을 누르면 레시피로 간다 (보관한 레시피면 링크 없음). 메뉴 옆 ×로 뺀다.

```
10/7 (화) 오늘
  아침   토스트 · 우유
  저녁   된장찌개 · 계란말이 · 김치          [아빠]
         + 메뉴
10/8 (수)
  저녁   외식 🍽️
```

- 날짜 카드의 [+ 메뉴] → 창: 끼니(기본 저녁) · 종류(집밥 / 외식 / 배달) · 레시피 고르기(고르면 메뉴 이름이 채워짐) 또는 직접 입력 · 요리 담당. 외식 · 배달은 이름을 비우면 '외식' · '배달'로 넣는다.

### 4.2 레시피 — `/cooking/recipes`, `/cooking/recipes/new`, `/cooking/recipes/[id]`

- 목록: 검색창(요리 이름 **또는 재료 이름**으로 찾기, 예: '양파'), 태그 칩 필터(많이 쓴 순), 카드(제목 · 조리 시간 · 인분 · 태그).
- 등록 · 수정(`/cooking/recipes/[id]/edit`): 태그는 자주 쓰는 것(국·찌개 · 반찬 · 메인 · 밥·면 · 간식 · 아이 · 손님상)을 고르고, 나머지는 쉼표로 직접 쓴다.
  - **재료 · 조리 순서는 한 줄에 하나씩 쓰는 글상자**로 받는다 (블로그에서 붙여 넣기 쉽게). 행 추가 방식에서 바꿨다.
  - 재료 한 줄은 `이름 양단위 (메모)`로 나눈다: `양파 1/2개` → 양파 · 0.5 · 개, `두부 한 모` → 두부 · 1 · 모, `소금 약간` → 소금 · 메모 '약간', `마늘 3쪽 (다진 것)` → 메모 '다진 것'. 나뉘지 않으면 이름만 남긴다.
- 상세: 재료 · 순서 보기, [식단에 추가](날짜 · 끼니 · 요리 담당 고르기) [수정] [보관].

### 4.3 장보기 — `/cooking/shopping`

```
[ 무엇을 살까요?          ] [추가]
[이번 주 식단에서 가져오기]

채소·과일
 ☐ 양파 2개
 ☐ 대파 1단
육류·해산물
 ☐ 돼지고기 앞다리 600g
───────────────
산 것 (3)                   [정리]
 ☑ 두부 1모 · 엄마
```

- 빠른 추가는 "양파 2개"처럼 입력하면 이름 · 수량 · 단위를 나눠 저장한다 (레시피 재료와 같은 규칙, 나뉘지 않으면 이름만).
- 카테고리는 품목 이름으로 추정하고(채소·과일 / 육류·해산물 / 유제품·계란 / 양념·가공 / 생활용품 / 기타), 연필 버튼으로 바꿀 수 있다. 다음에 같은 이름을 넣으면 마지막으로 쓴 카테고리를 쓴다 (지운 항목은 기억하지 않는다).
- 연필 버튼 = 고치기 창: 이름 · 수량 · 단위 · 카테고리 · 메모, [지우기](잘못 넣은 항목, 실제로 지움).
- 체크한 항목은 아래 '산 것'으로 내려가고 누가 샀는지 보인다. [정리]를 누르면 목록에서 숨긴다.

**식단에서 가져오기** (`/cooking/shopping/import`): 기간(기본: 오늘~이번 주 일요일, 최대 31일) 선택 → 집밥 메뉴의 레시피 재료를 합쳐 미리보기(어느 메뉴에 들어가는지 함께) → 집에 늘 있는 양념(간장 · 소금 · 된장 · 고춧가루 · 다진 마늘 등)은 기본으로 체크 해제 → [장보기에 N개 추가]. 레시피 없이 이름만 쓴 메뉴는 재료를 알 수 없어 따로 알려 준다.

## 5. 규칙

- **식단 메뉴 이름**은 레시피를 골라도 `title`에 복사해 둔다. 레시피를 보관해도 식단은 그대로 보인다.
- **재료 합치기**: 이름(앞뒤 공백 제거 · 소문자) + 단위가 같으면 수량을 더한다. 단위가 다르면 별도 행. 수량이 없는 재료('약간')는 하나로 합친다.
- **장보기 중복**: 체크 안 된 같은 이름 + 단위 항목이 이미 있으면 새로 만들지 않고 수량을 더한다.
- **체크**하면 `checked_by_member_id` · `checked_at`을 기록하고, 체크를 풀면 비운다.
- **정리**는 체크된 항목에 `cleared_at`을 넣는다 (삭제하지 않음 → 구매 이력).
- **동시 사용**: MVP는 화면에 다시 들어오거나 앱으로 돌아올 때 새로 불러온다. 체크는 낙관적 업데이트로 즉시 반영한다.
- **지난주 복사**는 비어 있는 칸(날짜 + 끼니)에만 채운다 (이미 있는 메뉴를 덮어쓰지 않음). 다시 눌러도 겹치지 않는다.
- **레시피 보관**: 관리자 이상, 또는 만든 사람. 보관해도 식단의 메뉴 이름은 남고, 링크만 사라진다.
- 식단 · 장보기는 승인된 구성원 누구나 바꿀 수 있다.

## 6. 활동 로그

| action | 언제 | payload |
|---|---|---|
| `recipe.created` | 레시피 등록 | title |
| `meal_plan.entry_added` | 식단에 메뉴 추가 | date, mealType, title |
| `meal_plan.week_copied` | 지난주 복사 | fromWeek, toWeek, count |
| `shopping_item.added` | 장보기 추가 (일괄 추가는 1건) | name / count |
| `shopping_item.checked` | 체크 | name |
| `shopping_list.cleared` | 정리 | count |

## 7. 대시보드에서 보여 줄 수 있는 것 (참고)

- 이번 주 식단 채움률, 오늘 메뉴 · 요리 담당
- 구성원별 요리 담당 횟수, 외식 · 배달 빈도
- 자주 먹은 메뉴, 자주 산 품목
