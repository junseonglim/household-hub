# 01. 개요

> 상태: v0.3 · 2026-10-12 (육아를 MVP 범위로)

## 1. 배경과 목적

집안일 정보가 머릿속, 메신저, 메모 앱에 흩어져 있으면 이런 문제가 생깁니다.

- 반복되는 일(이불 빨래, 냉장고 정리 등)을 마지막으로 언제 했는지 기억나지 않는다.
- 누가 무엇을 하고 있는지 서로 잘 보이지 않아 분담이 불공평하게 느껴진다.
- 곧 아이가 태어나면 챙길 일이 크게 늘어난다.

이 시스템은 **우리 가족이 한곳에서 집안일을 계획하고, 기록하고, 공유**하도록 돕는 **우리 집 전용** 웹 앱입니다.

## 2. 목표 (MVP 성공 기준)

1. 가족 구성원이 초대 코드 없이 가입하고, 관리자가 승인하면 바로 함께 쓸 수 있다.
2. 반복 청소 일을 등록하면 다음 예정일이 자동으로 계산되고, 휴대폰에서 한 번 탭으로 완료할 수 있다.
3. 한 주의 식단을 함께 짜고, 식단에서 장보기 목록을 만들어 장 보면서 체크할 수 있다.
4. 모든 완료·기록에 "누가, 언제"가 남아, 이후 대시보드에서 집계할 수 있다.
5. 무료 클라우드(Vercel + Neon)에 배포해 집 밖에서도 휴대폰으로 쓸 수 있다.

## 3. 범위

| 구분 | 포함 (MVP) | 이후 단계 |
|---|---|---|
| 공통 | 회원가입(관리자 승인)·로그인, 구성원 역할, 설정, 클라우드 배포 | 대시보드, 푸시 알림, 소셜 로그인(카카오 등), 오프라인 지원 |
| 청소 | 공간, 반복 할 일, 완료 체크·기록, 기본 템플릿 | 담당 순번 로테이션, 하위 체크리스트, 사진 |
| 요리 | 레시피, 주간 식단표, 장보기 목록 | 냉장고 재고·유통기한, 메뉴 추천, 레시피 URL 자동 가져오기 |
| 육아 | 출산 준비 체크리스트, 신생아 기록(수유 · 기저귀 · 수면 · 체온 · 약), 예방접종 · 검진 일정, 성장 · 발달 기록 ([모듈 문서](modules/childcare.md)) | 성장 백분위, 알림, 사진, 이유식 |

**하지 않는 것**: 다른 가정의 사용(우리 집 전용), 네이티브 앱, 가계부·재무.

## 4. 사용자

| 사용자 | 역할 | 주요 사용 장면 |
|---|---|---|
| 주 관리자 (처음 가입한 사람) | owner | 가입 승인, 할 일·식단 설계 |
| 배우자 | admin | 가입 승인, 할 일 완료, 식단·장보기 |
| 조부모·돌봄 도우미 (필요하면) | member | 오늘 할 일 확인, 완료 체크 |
| 아이 (출산 예정) | — | 계정이 아니라 육아 모듈의 기록 대상 (`child`). 둘 이상도 가능 |

사용 환경은 **휴대폰이 대부분**입니다(장 보는 중, 집안일 하면서 한 손으로). 식단 짜기나 할 일 설계 같은 계획 작업은 PC에서도 합니다.

## 5. 용어

| 용어 | 코드 이름 | 뜻 |
|---|---|---|
| 가구 | household | 우리 집. 앱 안에 하나만 존재 |
| 구성원 | member | 가구에 속한 사용자 계정. 역할(owner/admin/member)과 상태를 가짐 |
| 승인 대기 | pending | 가입은 했지만 관리자가 아직 승인하지 않은 상태. 어떤 데이터도 볼 수 없음 |
| 공간 | space | 집 안의 구역 (거실, 주방, 욕실 …) |
| 할 일 | task | 반복되거나 1회성인 해야 할 일. 공통 엔진으로 관리 |
| 반복 규칙 | recurrence | 할 일이 언제 다시 돌아오는지에 대한 규칙 |
| 완료 기록 | task completion | 누가 언제 할 일을 완료했는지 |
| 식단 | meal plan | 날짜 × 끼니별 메뉴 계획 |
| 활동 로그 | activity log | 모든 모듈의 주요 행동을 시간순으로 쌓는 공통 기록 (대시보드 재료) |

## 6. 설계 원칙

1. **모바일 우선, 빠른 입력** — 완료 체크는 1탭.
2. **모듈은 독립적으로** — 청소·요리·육아는 서로 직접 의존하지 않고 공통 기능(core)에만 의존한다. 새 모듈을 추가할 때 기존 모듈을 고치지 않는다.
3. **기록은 남긴다** — 완료·기록에는 항상 행위자와 시각을 저장한다. 대시보드는 나중에 만들어도 데이터는 지금부터 쌓인다.
4. **단순하게 시작** — 사용자는 우리 가족뿐. 캐시, 메시지 큐, 마이크로서비스는 쓰지 않는다.
5. **가족 데이터는 소중하게** — 클라우드에 저장되므로 HTTPS, 가입 승인, 정기 백업을 기본으로 한다.
